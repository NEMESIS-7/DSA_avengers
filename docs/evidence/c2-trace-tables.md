# C2 Trace Tables — Heap & Dijkstra

Generated by running `gsoo.algorithms.c2_dijkstra.DijkstraTraceDemo`, which rebuilds
the real road graph straight out of the committed seed data
(`sql/seed/locations_seed.sql` + `sql/seed/roads_seed.sql` — no live DB needed, so
reproducible from a clean checkout) and runs traced Dijkstra on it. The numbers
below are copied directly from that run, not typed by hand.

```
mvn exec:java -Dexec.mainClass=gsoo.algorithms.c2_dijkstra.DijkstraTraceDemo
```

Dataset rebuilt: 50 locations, 98 roads (the graph API rejects parallel edges, so
two of the 100 seeded roads — a flood-prone duplicate of `EXT-H02 -> GATE-01` —
never enter the graph; same dedup the live `Session.load()` performs).

Edge weights are `Config.effectiveEdgeCost(travelTimeSecs, roadConditionWeight)`:
`travelTime x roadConditionWeight`, plus the index-derived `ROUTE_PENALTY` (2.6)
on flood-prone roads (weight >= 1.5). Each step below shows the node Dijkstra
**finalized**, its settled distance, its predecessor on the shortest path, and how
many of its outgoing edges produced an actual relaxation improvement.
