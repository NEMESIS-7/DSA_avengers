## Dataset and parameter summary

This trace is generated by `KnapsackTraceDemo` from the project's real
`service_requests_template.csv` dataset.

- Service requests loaded: **300**
- Pending request candidates: **38**
- Index-number sum `S`: **6316**
- `URGENCY_WEIGHT`: **2**
- `SHIFT_BUDGET_MINUTES`: **316**
- Full DP table dimensions: **39 × 317**

The current database has no estimated-service-duration column. The hospital
adapter therefore uses the recorded SLA window as a transparent planning-time
proxy:

`time cost = deadlineAt - submittedAt`, measured in minutes

The item value is:

`priority value = urgency × Config.URGENCY_WEIGHT`

The DP algorithm is independent of these mapping rules. If an
`estimated_service_minutes` field is added later, only
`HospitalKnapsackPlanner` needs to change.

## Recurrence

For item `i` and capacity `m`:

```text
DP[i][m] = DP[i - 1][m]                         if item i is too large

DP[i][m] = max(
    DP[i - 1][m],
    value[i] + DP[i - 1][m - minutes[i]]
)                                                otherwise
```

The implementation creates every capacity column from `0` through `316`.
Selected columns are shown below so the evidence remains readable.
