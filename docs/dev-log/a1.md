**What broke:**
- `binarySearch()`'s two recursive branches were swapped (searched right when it should search
  left, and vice versa). Against the real dataset it doesn't converge — `left`/`right` collapse to
  `(0, -1)` and stay there, so it recurses forever. Caught as a `StackOverflowError` on the first
  test run. Fixed the branch directions and added the missing `left > right` base case
  (previously there was no way to signal "not found" — the old code's `return 0` was dead and
  would have been wrong anyway, since 0 is a valid index).
- `DynamicArray.grow()` didn't handle growing from zero capacity — `0 * 2 = 0`, so
  `new DynamicArray<>(0)` followed immediately by `add()` threw
  `ArrayIndexOutOfBoundsException`. Not caught by the original test suite, since the existing
  boundary test constructed a zero-capacity array but never called `add()` on it. Added a
  regression test alongside the fix.
- Also found and fixed two unrelated package-declaration bugs while integrating other members'
  merged slots into `Main`: `b1_quicksort/QuickSort.java` had no `package` line at all (default
  package), and `a3_stack/Stack.java` declared `package gsoo.structures;` instead of
  `gsoo.structures.a3_stack` — collided with the parent package where `Graph` lives. Fixed both,
  plus the files that depended on the wrong one (`AuditTrailDemo`, `StackTest`).

**Decided:**
- `DatabaseLoader`'s model classes (`Location`, `Road`, `Resource`, `ServiceRequest`) are now
  public (were package-private, so nothing outside `gsoo.db` could use them) — each moved to its
  own file since Java requires a public top-level class to match its filename.
- `Main`'s menu is a plain registry (`MenuItem[]`), one entry per finished slot, so wiring in a
  newly-merged slot is a two-line addition rather than a rewrite — most of the 15 slots are
  still in progress, so `Main` has to tolerate that permanently, not just for now.
