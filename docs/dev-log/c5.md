**Done:**

  priority value 50.
- Drafted the C5 report section and evidence document.
- Compiled all main project sources and ran independent normal, boundary,
  invalid-input and real-data smoke checks successfully.

**What broke or was missing:**

- The service-request schema has no explicit estimated-duration field, even
  though knapsack needs a time cost for every request.
- The submitted ZIP is a source snapshot without Git metadata, so branch and
  commit state must be handled in the local repository.
- Maven was unavailable in the verification environment. The final JUnit and
  whole-project Maven lifecycle must therefore be run in the local project
  before the pull request is opened.

**Decided:**

- Keep the core `Knapsack` class generic rather than making dynamic programming
  depend directly on JDBC or the graph.
- Use the recorded SLA window as an explicitly documented planning-time proxy
  instead of inventing hidden category durations.
- Use `urgency × Config.URGENCY_WEIGHT` as the integer optimisation value.
- Keep the full two-dimensional DP table because C5 owns both table evidence
  and reconstruction evidence.
- Treat ties deterministically by keeping the earlier solution when including
  a later item gives the same value.
- Change only the hospital adapter if the database later gains a true
  estimated-service-duration field.
