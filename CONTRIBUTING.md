# Contributing

New to the repo? Start with `docs/starting-your-slot.md` — this file covers the workflow rules; that one walks you through your first branch step by step.

## Branch workflow

1. Find your slot ID in `README.md` §4.
2. Branch off `develop`: `git checkout develop && git pull && git checkout -b feature/<slot-id>-<short-name>`
   (e.g. `feature/c2-heap-dijkstra`)
3. Work in your assigned folders:
   - `src/main/java/gsoo/structures/<your-slot-slug>/`
   - `src/main/java/gsoo/algorithms/<your-slot-slug>/`
   - matching folders under `src/test/java/gsoo/`
4. Commit early, commit often — small commits are easier for your pod lead to review than one giant diff at the deadline.
5. Open a PR into `develop`. Your pod lead reviews against the Definition of Done below before merging.
6. Delete your feature branch after merge.
7. Update your card on the Notion Slot Board as you go — status and the four Definition-of-Done checkboxes.

Never push directly to `main` or `develop`. One branch per person per slot — not a shared branch per pod (see README §3–4 for why).

## Definition of Done (checked at PR review)

- [ ] Implementation matches the frozen interface, no banned built-ins (`HashMap`, `TreeMap`, `PriorityQueue`, `Stack`, `ArrayDeque`, etc.)
- [ ] Three tests: normal case, boundary case, invalid input
- [ ] Trace output generated by your code from the real dataset (not hand-written)
- [ ] Report section drafted into the shared report skeleton
- [ ] Dev-log entry for the week: what was done, what broke, what was decided

A PR missing any of these gets requested changes, not a merge.

## Milestone tags

At the end of each week, once `develop` is merged into `main`, the Architect tags the commit:
`m1-foundations`, `m2-structures`, `m3-algorithms`, `m4-report`.

## Interfaces are frozen after Week 1

Once your structure or algorithm's public interface is merged to `develop` in Week 1, changing its signature requires a conversation with the Architect and everyone downstream of it — not a silent breaking change on your feature branch.
